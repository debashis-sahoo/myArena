# Tasks: Gameplay Clarity and Audio Polish

**Input**: Design documents from `/specs/007-polish-gameplay-audio/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md)

**Tests**: No automated unit or integration tests (user policy and constitution Principle III; none were requested). Each story ends with a **browser-based verification** task that records
scenario, expected and observed results (screenshots, measurements or script output) in `specs/007-polish-gameplay-audio/verification.md`, with images under
`specs/007-polish-gameplay-audio/evidence/` (`<scenario>-<width>x<height>.jpg`). Scripted Socket.IO clients, the loudness meter and the contrast script live outside the repository (for
example `%TEMP%\ludo-verify`, `%TEMP%\audio-meter`, `%TEMP%\housie-contrast`). The existing `npm run smoke` is run as a regression check (T008, T066) and is not extended.

**Organization**: Tasks are grouped by user story in priority order (the five P1 stories, then the two P2 stories). The stories are independent of each other once Phase 2 is done; the few
shared files are called out in "Dependencies" so two stories never edit the same file at once.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an incomplete task)
- **[Story]**: Maps to the user story in [spec.md](spec.md) (US1 to US7)
- All paths are relative to the repository root `G:\Projects\MyArena`

## Path Conventions

Existing npm workspaces (see [plan.md](plan.md) Project Structure): `shared/src/`, `server/src/`, `client/src/`. Values, constants, wire shapes and refusal texts come from
[data-model.md](data-model.md), [contracts/](contracts/) and [research.md](research.md); do not invent different ones. **No new dependencies and no binary assets** are added.

**Naming**: `shared/src/index.ts` re-exports every module with `export *`. Ludo exports are unprefixed and UNO exports are prefixed `Uno*` / `UNO_*` / `uno*`; new UNO constants keep the
`UNO_` prefix. Client-only constants (audio, Housie) are not exported from `shared`. Every platform change must leave Housie, Bingo and UNO behaving exactly as before except for the
documented additions.
