# Tasks: UNO Multi-Player & AI Game Module

**Input**: Design documents from `/specs/006-uno-game-module/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md)

**Tests**: No automated unit or integration tests (user policy and constitution Principle III). Each story ends with a **browser-based verification** task that records scenario,
expected and observed results (screenshots, measurements or script output) in `specs/006-uno-game-module/verification.md`. Scripted Socket.IO clients for races, bot legality and the
privacy audit live outside the repository (for example `%TEMP%\uno-verify`). The existing `npm run smoke` is extended by one assertion (T030) and re-run as a regression check (T023, T087).

**Organization**: Tasks are grouped by user story. Because the game is only playable once several stories exist, the P1 stories are ordered by dependency (solo start and table, a turn,
action cards, then bots, UNO! and catching, then the online room), followed by chat (P2), finishing (P3) and the layout pass (P2). **The solo game is first playable end to end after
Phase 6 (US1, US3, US4, US7).** Phases are listed in execution order, not strict priority order.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an incomplete task)
- **[Story]**: Maps to the user story in [spec.md](spec.md) (US1 to US9)
- All paths are relative to the repository root `G:\Projects\MyArena`

## Path Conventions

Existing npm workspaces (see [plan.md](plan.md) Project Structure): `shared/src/uno/`, `server/src/games/uno/`, `client/src/games/uno/`, plus opt-in changes to Platform Core files
([contracts/platform-integration.md](contracts/platform-integration.md)). Constants, rules and wire shapes come from [data-model.md](data-model.md), [contracts/uno-protocol.md](contracts/uno-protocol.md)
and [research.md](research.md); do not invent different values.

**Naming**: `shared/src/index.ts` re-exports every module with `export *`, and Ludo already exports `TURN_TIMER_MS`, `AWAY_WARN_AT`, `AWAY_RELEASE_AT`, `BOT_PAUSE_MS` and `BOT_THINK_MS`. Every
UNO export is therefore prefixed (`Uno*` for types, `UNO_*` for constants, `uno*` for functions). The design documents write `cardOf`, `TURN_TIMER_MS` and the like for readability; the code
names are `unoCardOf`, `UNO_TURN_TIMER_MS`, `UNO_AWAY_WARN_AT`, `UNO_CATCH_WINDOW_MS` and so on. UNO never calls `ctx.say`, `ctx.notice` or `ctx.emit` (no chat line, no broadcast of
private data); it sends events with `ctx.emitTo` to each human. Every platform change must leave Ludo, Housie and Bingo behaving exactly as before.
